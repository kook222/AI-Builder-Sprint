# FactTrace

구글 검색 결과에 나온 링크들의 **본문을 실제로 읽어보고**, 검색어와 상관없는 광고성 글인지
피싱을 노린 사이트인지 판단해서 제목 옆에 표시해주는 크롬 확장 프로그램입니다.

판단은 Upstage **solar-pro3** 모델이 합니다.

## 무엇을 하는가

**1. 검색 결과 목록에서**

검색을 하면 결과 링크의 본문을 직접 가져와 모델에게 물어보고, 제목 옆에 표시를 답니다.
결과를 **하나씩 따로** 판정해서 먼저 끝난 것부터 표시됩니다. 첫 표시는 3초쯤에 뜹니다.

| 표시 | 붙는 조건 |
|---|---|
| 피싱 의심 | 자동으로 다른 사이트로 튕겨 보내거나, 겁주고 재촉해서 특정 외부 사이트로 몰아가는 경우. 그 끝에서 비밀번호·카드번호를 넣게 하거나 유명 서비스를 사칭하는 경우. **외부 링크가 있다는 것만으로는 붙지 않습니다.** |
| 광고성 | **검색어와의 관련성을 먼저 봅니다.** 검색어가 묻는 것에 답하지 않으면서 무언가를 팔고 있으면 광고성입니다. 답하고 있더라도 제휴 링크·협찬 고지로 결국 파는 글이면 광고성입니다. **관련성이 높으면 배너가 몇 개든 광고성으로 보지 않습니다.** |
| 로그인 필요 | 로그인하지 않으면 **본문 전체를 읽을 수 없는** 경우로만 한정. 댓글용 로그인 안내나 구석의 로그인 버튼은 해당하지 않습니다. |

문제가 없는 결과에는 **아무것도 붙지 않습니다.** 표시가 뜬다는 것 자체가 신호입니다.

표시에 마우스를 올리면 **왜 그렇게 판단했는지**와 함께
**본문의 어느 부분이 의심스러운지**가 그대로 나옵니다.
지어낸 문장이 섞이지 않도록, 본문에 실제로 있는 문장만 골라서 보여줍니다.

**2. 주소만으로 못 읽는 사이트는 들어갔을 때 판정합니다**

요즘 사이트는 화면을 자바스크립트로 그립니다. 네이버는 받아온 HTML이 225KB인데 글자는 113자뿐입니다.
쿠팡이나 지마켓처럼 아예 403으로 막는 곳도 있습니다. 흔한 사이트 17곳을 재보니 8곳이 이랬습니다.

이런 주소는 검색 단계에서 판단을 보류하고 적어만 둡니다.
사용자가 실제로 그 페이지를 열면 **브라우저가 이미 다 그려놓은 글자**로 그때 판정합니다.
한 번 판정하고 나면 다음 검색부터는 배지가 바로 뜹니다.

**3. 광고성 · 피싱으로 걸리면 칠할 곳을 미리 뽑아둡니다**

배지를 띄운 직후, 그 페이지의 어느 문장이 광고이고 어느 문장이 피싱인지를 뽑아 적어둡니다.
사용자가 아직 검색 결과를 보고 있는 동안 백그라운드에서 끝납니다.

**4. 그 결과를 누르면 실제 사이트에서 곧바로 칠해집니다**

원래 사이트가 평소대로 열리고, 미리 적어둔 문장에 **붉은 하이라이트**가 들어갑니다.
맨 위에 무엇이 왜 걸렸는지 띠가 뜹니다.

페이지가 열릴 때는 **모델을 부르지 않습니다.** 답이 이미 준비돼 있어서 조회에 1ms도 걸리지 않습니다.
페이지 본문을 밖으로 보내지도 않습니다. 보내는 건 주소뿐입니다.

준비가 아직 안 끝났으면 끝나는 대로 반영됩니다.
표시가 안 붙은 정상 결과는 아무것도 하지 않습니다.

## 설치

1. 크롬 주소창에 `chrome://extensions` 를 엽니다
2. 오른쪽 위 **개발자 모드**를 켭니다
3. **압축해제된 확장 프로그램을 로드** 를 누르고 이 폴더의 `extension` 을 고릅니다
4. 주소창 옆 아이콘을 눌러 팝업을 열고 **API 키** 칸에 Upstage 키를 넣습니다

별도로 띄워야 할 서버는 없습니다.

## 사용

주소창 옆 아이콘을 누르면 팝업이 뜹니다.

- **켜짐 / 꺼짐** — 스위치 하나로 전체를 끄고 켭니다
- **API 키** — Upstage 키를 넣는 곳. 이게 없으면 판정이 돌지 않습니다
- **log 폴더에 저장** — 모델에 보낸 것과 받은 것을 전부 담아
  `다운로드/log/fact-trace-날짜.log` 로 내려받습니다
- **비우기** — 쌓인 기록을 지웁니다

## 동작 확인용 데모

진짜 피싱 사이트를 찾아다닐 필요 없이, 하이라이트가 제대로 되는지 볼 수 있는
가짜 페이지가 들어 있습니다.

```bash
python3 -m http.server 8899
```

띄운 뒤 `http://localhost:8899/demo/index.html` 로 들어가면 됩니다.
이 페이지는 모델 응답을 흉내 내서 실제 `extension/content/page.js` 를 그대로 돌립니다.
문장이 `<strong>` 이나 `<span>` 으로 잘려 있는 까다로운 경우까지 포함돼 있고,
맨 아래에 몇 군데를 칠했는지, 칠하면 안 되는 곳을 건드리진 않았는지 채점 결과가 나옵니다.

같은 폴더의 `demo/ad.html` 과 `demo/phish.html` 은 판정 자체를 시험해보기 위한 가짜 페이지입니다.
광고 스크립트와 쿠팡 제휴 링크를 잔뜩 넣은 것, 계좌 정보를 요구하며 외부로 튕겨보내는 것입니다.

## 파일 구성

```
extension/
├── manifest.json
├── background.js          확장의 본체. 아래 흐름을 지휘한다
├── lib/
│   ├── solar.js           solar-pro3 호출 (test.js를 fetch로 옮긴 것)
│   ├── prompts.js         모델에게 주는 지시문. 판정 기준은 여기만 고치면 된다
│   ├── article.js         링크 본문 긁어오기, 광고·리다이렉트·로그인벽 증거 수집
│   ├── verify.js          모델이 지어낸 판정을 걸러내는 곳
│   └── logger.js          모델 입출력 기록
├── content/
│   ├── serp.js            구글 검색 결과에 표시 달기
│   ├── page.js            방문한 페이지에 하이라이트 칠하기
│   └── style.css
├── popup.html
└── popup.js

demo/index.html            동작 확인용 가짜 피싱 페이지
test.js                    받은 API 예제 원본
```

## 흐름

```
구글 검색
   ↓  content/serp.js 가 결과를 하나씩 따로 보낸다 (동시에 최대 5건)
background.js
   ↓  lib/article.js 로 그 링크의 본문을 가져온다
   ↓  lib/prompts.js 의 지시문으로 solar-pro3 에 물어본다
   ↓  lib/verify.js 로 근거를 대조해 지어낸 판정을 버린다
   ↓  광고·피싱이면 그 주소를 적어둔다
content/serp.js 가 답이 오는 대로 제목 옆에 표시를 단다

   ↓  본문을 못 읽는 사이트면 판단을 보류하고 적어만 둔다
   ↓  광고·피싱이면 이어서 칠할 문장을 뽑아 적어둔다

사용자가 그 결과를 클릭
   ↓  원래 사이트가 평소대로 열린다
   ↓  content/page.js 가 이 주소에 칠할 곳이 있는지 물어본다 (모델 호출 없음)
   ↓  보류해둔 주소면 화면에 그려진 글자를 보내서 그때 판정한다
content/page.js 가 그 문장들에 붉은 칠을 하고 경고 띠를 띄운다
```

## 판정을 어떻게 믿을 만하게 만들었나

모델에게 그냥 물어보면 근거가 빈약하거나, 아예 없는 근거를 지어냅니다.
실제로 "특이사항 없음"이라고 적혀 있는 페이지에 *"쿠팡 제휴 링크 3개"* 라는
이유를 붙여 광고 딱지를 다는 일이 있었습니다. 그래서 세 겹으로 막았습니다.

**1. 증거를 세어서 같이 준다** (`lib/article.js`)

글만 읽고 "배너가 많은지"를 판단하는 건 무리입니다. 그건 우리가 셀 수 있습니다.

- 광고 스크립트가 몇 종인지 (그리고 그게 흔한 수준인지 많은 편인지)
- 협찬·수수료 고지 문구, 제휴 링크가 있는지
- `meta refresh`나 스크립트로 외부 주소를 자동으로 여는지
- 실제 `<a>` 링크가 어느 도메인으로 몰려 있는지
- 본문이 로그인 창에 막혀 있는지

**2. 근거 원문을 인용하게 하고, 코드로 대조한다** (`lib/verify.js`)

라벨을 붙일 때 근거가 된 문장을 원문에서 그대로 옮기게 합니다.
그 문장의 낱말이 실제 원문과 70% 이상 겹치지 않으면 **판정을 통째로 버립니다.**
없는 말을 지어내면 그 낱말이 원문에 있을 리 없으니 여기서 걸립니다.

**3. 모르는 건 위험하다고 하지 않는다**

본문을 못 가져온 페이지(403, 타임아웃)에는 어떤 라벨도 붙이지 않습니다.
크롤러만 막고 사람에게는 멀쩡히 보여주는 사이트가 많기 때문입니다.

`effort`는 `high`로 둡니다. 검색당 10초쯤 더 걸리지만, `low`에서는
멀쩡한 블로그에 광고 딱지가 붙고 아무 문제 없는 문단에 붉은 칠이 됐습니다.

**4. 서비스 워커가 먼저 죽지 않게 붙잡는다** (`background.js`)

MV3 서비스 워커는 30초 놀면 꺼지는데 `fetch`는 그 타이머를 갱신하지 않습니다.
모델 응답을 20초 넘게 기다리다 워커가 먼저 죽으면 답을 받을 곳이 없어집니다.
짧은 호출인 검색 배지는 멀쩡한데 오래 걸리는 하이라이트만 안 뜨는 증상이 여기서 나왔습니다.
분석이 도는 동안 확장 API를 20초마다 건드려 타이머를 되돌립니다.

## 알아둘 점

- **API 키는 코드에 없습니다.** 확장을 설치한 뒤 팝업의 `API 키` 칸에 Upstage 키를 넣어야 동작합니다.
  키는 `chrome.storage.local` 에만 저장되고 저장소에는 올라가지 않습니다.
- 본문을 가져올 때 쿠키를 보내지 않습니다(`credentials: 'omit'`). 그래서 로그인해야 보이는
  사이트는 로그아웃 상태로 보이고, 덕분에 로그인 벽을 알아챌 수 있습니다.
- **하이라이트는 검색에서 광고·피싱으로 걸린 주소에만 동작합니다.** 그 밖의 페이지에서는
  주소를 확인하고 바로 끝납니다. 본문을 밖으로 내보내지 않습니다.
- 구글은 나라마다 도메인이 달라서(`google.co.kr`, `google.co.jp` …) 매니페스트 패턴 대신
  모든 페이지에 얹은 뒤 코드에서 걸러냅니다. 어느 나라 구글에서든 동작합니다.
- 검색 결과마다 모델을 한 번씩 부릅니다. 동시에 최대 5건까지 돌아갑니다.
  첫 표시는 3초, 전부 끝나기까지 12초쯤 걸립니다. 정확도를 위해 일부러 느리게 두었습니다.
- 판정이 너무 깐깐하거나 무르면 `lib/prompts.js` 의 문구를 조절하세요.
  다른 파일은 손댈 필요가 없습니다.
